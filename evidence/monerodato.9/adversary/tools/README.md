# Public corpus tools

Entry-point commands (all options shown are REQUIRED; there are no default
endpoints, ports, or credential paths):

```
# label_oracle.py — digest-auth RPC client that labels raw transactions
python3 label_oracle.py --endpoint HOST:PORT --credential-file PATH smoke
python3 label_oracle.py --endpoint HOST:PORT --credential-file PATH label parents.jsonl labels.json
python3 label_oracle.py --endpoint HOST:PORT --credential-file PATH label-mut parents.jsonl mut-out 100

# fork_compare.py — compares live fork-vs-stock verdicts over the corpus
python3 fork_compare.py 1 outdir --corpus-dir CORPUS --stock-endpoint HOST:PORT --fork-endpoint HOST:PORT --credential-file PATH
python3 fork_compare.py 2 outdir --corpus-dir CORPUS --stock-endpoint HOST:PORT --fork-endpoint HOST:PORT --credential-file PATH
python3 fork_compare.py parm-mut outdir --corpus-dir CORPUS --stock-endpoint HOST:PORT --fork-endpoint HOST:PORT --credential-file PATH

# mutant_gen.py — offline structured tx-prefix mutant generation (no RPC)
python3 -I mutant_gen.py --parents parents.jsonl --outdir corpus-parm-mut

# corpus_generator.py — offline rejection-corpus generation from test vectors
python3 corpus_generator.py gen vectors_dir out_dir 2000
python3 corpus_generator.py check out_dir verdicts.json

# convert_progress.py — progress.json to per-case CSV (no RPC)
python3 -I convert_progress.py --progress-dir COMPARE_ROOT --out-dir CSV_OUT
```

`HOST:PORT` placeholders stand for the RPC endpoint of the daemon being
queried; `PATH` is a plain text credential file of `key: value` lines and
must define the keys `user` and `password` (the RPC digest credentials).
`CORPUS` is the corpus data directory (case sets and labels); the tools
take it as an argument and never derive data paths from their own
location.

## What each tool does

**label_oracle.py** is a JSON-RPC client for a stock daemon's RPC interface
using persistent-connection HTTP digest auth (the authenticated request
reuses the TCP connection that received the 401 challenge, with the nonce
count incrementing). It offers an authenticated `get_info` smoke check, a
batch labeler that submits raw transactions from a JSONL export with
`do_not_relay=true` and records accept/reject reason classes, and a mutation
mode that byte-flips exported parents and labels the resulting mutants live.
It rate-limits itself with a fixed inter-request delay and flushes the
transaction pool after any accepted transaction.

**fork_compare.py** replays a corpus (must-accept parents plus recorded
mutants, or the offline `parm-mut` mutant set) against two live daemons —
the stock build and the fork under test — and verifies that the two agree
with each other and with any previously recorded labels. Mismatching cases
are appended to `outdir/mismatches.json`; `progress.json` makes it
resume-safe by case id.

**mutant_gen.py** is an offline generator (no RPC) that parses transaction
prefixes from the accept-parents corpus, calibrates itself by requiring an
exact parse-then-serialize round trip, and emits structured encoding mutants
(overlong varints, leading/trailing junk) and multi-input mutants
(duplicated, copied, swapped, or amount-bumped inputs) into
`corpus-parm-mut/` with a `labels.json` manifest; labels stay null because
these are compared live by `fork_compare.py parm-mut`.

**corpus_generator.py** is an offline generator (no RPC) that parses binary
FCMP++ verify-input test vectors, applies structured mutations (bit flips in
signature/pseudo-out/key-image regions, layer-count lies, key-image swaps),
and writes mutated cases plus an unmodified must-accept set with a JSON
manifest; its `check` mode later verifies recorded verdicts against the
manifest.

**convert_progress.py** is an offline formatter (no RPC) that turns the
`progress.json` resume files written by `fork_compare.py` into the
per-case CSV rows shipped under `../data/` (case id, both live verdicts,
the recorded verdict where one exists, and the match flag).
