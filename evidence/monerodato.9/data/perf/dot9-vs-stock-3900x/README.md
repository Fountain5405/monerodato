# monerodato.9 against stock on a 12-core desktop

**What this measures:** monerodato.9's monerod against stock on one machine, over three kinds of blocks, at two thread settings. Each setting gets the same three alternating rounds.

**Result:** .9 is faster and uses less CPU and memory in all six cells, with no overlap between the arms in any figure. Every run ended on the reference node's block hash.
- **Heavy blocks:** wall −61% at 24 threads and −53% at 12.
- **One-input big blocks:** wall −37% and −34%.
- **Ordinary small-tx blocks:** wall −19% and −12%.

## Setup
- **Machine:** AMD Ryzen 9 3900X (12 cores / 24 threads), 16 GB DDR4-2133, SATA SSD, Linux 6.8. CPU governor set to `performance` for the runs, and no other workload on the box.
- **Builds:** two static release builds, made the same way with the same toolchain (Ninja, Release, `STATIC=ON`, default `ARCH`, `BUILD_TESTS=OFF`):

| arm | code | monerod sha256 |
|---|---|---|
| **stock** | seraphis-migration v0.19.0.0-beta.3.1, `d80596ad1` | `e2e058db27c4bb949863e7f04c659fc4f22de4f3d31a696b6e23285493a93e2d` |
| **n9** | monerodato.9; its `src/` is identical to the tag's commit `12414472c` | `c44c62f156ef33c603368fecbf0ff6cc69cb53c0bda6b752c4d670dadc5eb144` |

- **The network:** a stressnet (testnet) chain, unpruned. Blocks come from one LAN peer only (`--add-exclusive-node`, written `<peer>` in the files).
- **Before each run,** the database is rewound to the window's start by popping blocks (`recipe/pop_to.sh`). The pop checks the new top block's hash against the peer's.
- **Each run** starts monerod and stops it once the log height reaches the window's end. The harness is `recipe/ab_window.sh` and the driver is `recipe/g021.sh`. Each run records:
  - **wall:** from launch to the log height reaching the window's end, including start-up;
  - **CPU:** the process's utime + stime at the stop;
  - **peak anon:** the highest RssAnon, sampled every 2 s (`recipe/sample.sh`; the per-run samples are `data/<cell>/rN_<arm>.mem.csv`);
  - **anon after 45 s idle:** RssAnon 45 s after the window's end.
- **After each run,** the top block's hash is read from an idle offline restart and compared with the peer's.
- **Cells and rounds:** each of the six cells runs 3 rounds. Stock runs first in odd rounds and n9 first in even ones.

| cell | blocks | settings |
|---|---|---|
| small-tx | 3,106,400-3,106,800 (ordinary small transactions) | defaults |
| heavy | 3,105,401-3,105,441 (large blocks; stock wedges on them at the default sync settings) | `--block-sync-size 5` in both arms |
| one-input big | 3,103,300-3,103,500 (big blocks of one-input transactions) | defaults |

Each cell runs at monerod's default thread count (24 here) and again at `--max-concurrency 12`.

- **Correctness:** all 36 runs ended on the peer's block hash (`hash_match` in `results.csv`).
- **Extra blocks:** a run can add a few blocks past the window's end before it stops (the `blocks` column: up to 412 of 400, 44 of 40, 203 of 200). Wall is timed to the window's end, so these blocks are not in it. CPU is read at the stop, so they are.
- **Fixed before the runs:** expected ranges for wall, CPU and peak anon. A missed range changes nothing in the rows.

## Limits
- One machine (Zen 2, 12 cores) and synthetic stressnet traffic.
- 40-, 200- and 400-block windows, not a whole sync.
- Wall includes start-up.
- The heavy cells run at `--block-sync-size 5` in both arms.
- Three runs a side.
