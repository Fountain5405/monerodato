# Methods: the HDD VM kits v10-v13 (monerodato.8's `--db-cache-drop`)

These are the scripts that ran the measurements in `data/perf/hddvm-dot8-kit10` to `hddvm-dot8-kit13`, and `hddvm-dot8-kit12r`. The scorers are `scripts/hddkit1x_table.py` and `scripts/hddkit12_pool_nocap.py`. `METHODS.md` ("The HDD VM kits") gives the metric, the bars and the results.

## What is here
| path | what |
|---|---|
| `kit10/` to `kit13/` | each kit's scripts as run, one directory per kit, as they sat on the VM |
| `kit13/test/` | the kit's offline self-test: a fake `monerod` and a fixture that check the driver's output lines without a disk or a chain |
| `build/build_pair13.sh` | the build of kit v13's two binaries |
| `ORIGINAL_SHA256SUMS` | the sha256 of every file **as run**, before the edits below |

In each kit directory:
| file | what |
|---|---|
| `hdd_stage1c.sh` | the stage driver: ARMS x ROUNDS runs, the arm order rotated each round; collects every run's RESULT, WINDOW, IOSTAT and CACHEDROP lines into one `results.txt` |
| `hdd_run.sh` | one run (kit v6 of the run script, the same file in all four kits): restore the database, drop the page cache, optionally start a cgroup scope with `MemoryMax`, start the samplers, sync from one peer to the target height, check the top block's hash, write `summary.txt` |
| `hdd_trace.sh`, `bioread_vm.bt`, `sampler_vm.py` | the traced diagnosis stage (arms W and V, kit v10 only): a block-I/O trace with bpftrace and a height sampler. The timing stages do not use them |

**Matching a script to its log:** each kit's `log.txt` names the run script, the stage script and the trace script with the first 16 hex digits of their sha256. Those hashes are in `ORIGINAL_SHA256SUMS`:
- `hdd_run.sh` d5f06d17df334fdc in every kit;
- `hdd_trace.sh` 5d89e47804c44caf;
- `hdd_stage1c.sh` aa8a10b8c45701c6 (v10), 9d8286fe308d7520 (v11), 2836f4e95caa0e0b (v12 and v12r), aca8a17e92045beb (v13).

**The published files differ from those in three ways only:**
- lab host and agent names in comments are replaced by "the peer" and "the lab coordinator";
- the lab user's home directory is written `$HOME`;
- in `hdd_stage1c.sh`, the default names of the run and trace scripts lose their mailbox prefix. `hdd_stage1c.sh` first looks for the run script under that prefixed name and then, as in this package, for `hdd_run.sh` next to it.

## The machine and the inputs
- **The VM:** 4 vCPUs, 4 GB RAM, no swap, Linux 6.8. Its data disk is a 5,400 rpm HDD.
- **The database:** a pruned stressnet (testnet) database at height 3,106,400, compacted (`SNAP_MDB`). It is copied onto the HDD before each run.
- **The peer:** one stressnet node on the LAN, synced past 3,113,400 (`PEER`, host:port of its P2P port). It is the only peer (`--add-exclusive-node`), and its top-block hash is the check.
- **Tools on the VM:** bash, python3, curl, sysstat (`iostat`, `pidstat`), systemd (for the memory cap), `fincore`, and sudo for `drop_caches`. bpftrace is needed only for the traced stage.

## The runs
Every run syncs 7,000 blocks, 3,106,401-3,113,400, with WINDOW lines every 1,000 blocks, and a timeout of 9,000 s. Each line below is one stage, run from the kit directory with `SNAP_MDB`, `DATA_DIR`, `PEER` and `OUT_BASE` set. `$K` is the directory holding the binaries.

| kit | arms | stages as run | published |
|---|---|---|---|
| v10 | F, N: one binary, `monerod-3f`; N sets `MONERODATO_NO_DROP_FREED=1` | `BIN_3F=$K/monerod-3f bash hdd_stage1c.sh` (no cap); `ARMS="W V" ROUNDS=1 BIN_3EWL=… BIN_3FWL=… bash hdd_stage1c.sh` (traced); `MEM_MAX=1536M BIN_3F=$K/monerod-3f bash hdd_stage1c.sh` | A, B (traced), C |
| v11 | F, N: `monerod-3g`, the same switch | `BIN_3G=$K/monerod-3g bash hdd_stage1c.sh`; then with `MEM_MAX=1536M` | A, B |
| v12 | F, N: `monerod-3h`; N sets the switch, which also turns the prefetch off | `BIN_3H=$K/monerod-3h bash hdd_stage1c.sh`; then with `MEM_MAX=1536M` | A, B |
| v12r | as v12, N first | `ARMS="N F" BIN_3H=$K/monerod-3h bash hdd_stage1c.sh` (no cap) | R |
| v13 | F: the .8 candidate; N: the .7 release; no switch in either | `BIN_F=$K/monerod-8 BIN_N=$K/monerod-7 bash hdd_stage1c.sh`; then with `MEM_MAX=1536M` | A, B |

- ROUNDS is 2 throughout (F N, then N F), so each stage is F N N F.
- The F arm removes the switch variables from monerod's environment. The N arm sets `MONERODATO_NO_DROP_FREED=1` (v10-v12). Kit v13 removes them in both arms.
- Each run's `summary.txt` names its binary with the first 16 hex digits of its sha256.

## The binaries
- **Kits v10-v12** ran prototype candidates (3f, 3g, 3h): monerodato.6 plus the LMDB page-cache-drop commits under development, built static (Release, `STATIC=ON`, default `ARCH`). Those prototype branches are in the pre-publication history, which is not public. Their sha256s:
  - `monerod-3f` `980c8a20692571e06d99c05d3de0fe85c567e68f37c39694b136366252518ff4`;
  - `monerod-3g` `1662a7e1ca57c86aced46283fd47a3ad98a6b49789ea8fb71451dcf23f4ceda8`;
  - `monerod-3h` `cdd580f3f4c9824dd80c6c7e0d9233aedf9925371fd8b7bf96932a58d2d7c1e9`.
- **Kit v13** ran the .7 release against the .8 candidate, both built by `build/build_pair13.sh`. That candidate had the drop always on. monerodato.8 as released made it opt-in (`--db-cache-drop`). `data/perf/3900x-dot8-option` and `3900x-dot8-equivalence` show that the release with the option behaves as that candidate, within 1%.
- **How `build_pair13.sh` builds:**
  - one build directory, `build/static-head`, configured once as Release, `STATIC=ON`, default `ARCH`;
  - for each commit: check it out, delete the stale Rust library (`libfcmp_pp_rust.a`), re-run cmake, run `ninja daemon`;
  - check that `monerod --version` names the commit, then record its sha256.
- **To rebuild from public refs:** build tags `v0.19.0.0-beta.3.1-monerodato.7` (`f3c4ea5d9`) and `v0.19.0.0-beta.3.1-monerodato.8` the same way. Run arm F of the .8 binary with `--db-cache-drop`. The .8 tag is the released form, not the candidate kit v13 ran, so its figures need not match exactly.

## Limits
- One VM, one HDD, one peer on the LAN. Other lab traffic on the peer moved capped N runs by up to 9% in kit v10.
- The prototype binaries of kits v10-v12 cannot be rebuilt from public refs. Kit v13's can.
