# Methods: the 3900X sync runs behind monerodato.8 (`--db-cache-drop`)

These are the scripts that ran the measurements in four published directories:
- `data/perf/3900x-dot8-writes`
- `data/perf/3900x-dot8-prefetch-s0z`
- `data/perf/3900x-dot8-equivalence`
- `data/perf/3900x-dot8-option`

`METHODS.md` ("Pruning's prefetch on the 3900X" and "The release against its prototype, and the option") gives the bars and the results. The published scorers are in `scripts/`.

## What one run is
`run/g016s0_run.sh <name> <MemoryMax or infinity>` runs on the 3900X. One run:
- syncs a test node from height 3,106,400 to `TOP`, from one local source node: a stock node on a synced copy of the stressnet database, P2P on 127.0.0.1:28180;
- runs the test node inside a transient systemd scope with that `MemoryMax` and no swap, as the given binary (`BIN_OVERRIDE`), behind `NODE_WRAP` (for example `taskset -c 0-3`), with `EXTRA_ARGS`;
- records:
  - every block-layer I/O on the data disk (`bioread.bt`, bpftrace);
  - 1 s samples of height and CPU (`sampler.py`);
  - the page-cache map of `data.mdb` at the start and the end (`pagemap.c`, `pagemap2.c`; `residents.c` with `RESID=1`);
- writes `run.log`, ending `G016S0_RUN_DONE <why>`.

`run/g016s0_drive.sh <name:level[:binary]>...` runs on the control box. For each spec, it:
- restores the 3900X's working database from a stored snapshot (sha256-checked);
- starts `g016s0_run.sh` there;
- waits for the marker.

Its environment maps onto the runner's:

| driver | runner |
|---|---|
| `S0SNAP` | (the snapshot restored before the run) |
| `S0TOP` | `TOP` |
| `S0WRAP` | `NODE_WRAP` |
| `S0EXTRA` | `EXTRA_ARGS` |
| `RESID` | `RESID` |

**Databases:**
- `stressnet_h3106400` is a stressnet database at 3,106,400, which s0b, s0c and s0c2 started from.
- `stressnet_h3106400cp` is its compacted copy, pruned once with the stock daemon (`--offline --prune-blockchain`) and compacted again with `mdb_copy -c`. The s0z, dot8E and dot8F runs started from it.

## Limits
- One machine (Ryzen 9 3900X, SATA SSD) and one source node on the same machine. These runs measure reads, CPU and the page cache, not HDD timing; the HDD figures are the HDD VM kits'.
- One run per arm and level, except the equivalence check (two pairs).
