# fastbox kit: stock monerod (S) against the fork (E) on whole sync windows

## Purpose
The kit compares two monerod binaries on the Monero stressnet testnet. S is stock. E is the fork.
Each run syncs a fixed block window from a snapshot, as the G013 harness (`ab_window.sh`) did. It measures CPU, wall time, memory and I/O.
It then checks that the top block hash matches the peer's.

## The two windows
- **heavy:** snapshot `SNAP_HEAVY`, sync to height 3105444, timeout 1500 s. A short window of very heavy blocks.
  - Both arms run it with `--block-sync-size 5` (`HEAVY_EXTRA`). At the default span size, stock cannot sync these blocks: a 20-block request of them exceeds the levin packet limit, and it wedges at 3,105,401. Every earlier stock figure for this window (G014, E032) used size 5 in both arms, so the binary stays the only difference.
- **small:** snapshot `SNAP_SMALL`, sync to height 3106800, timeout 2400 s. A longer window of small blocks.
  - Both arms run it at the default settings.

Both snapshots hold `testnet/lmdb/data.mdb`.

## Arms and thread settings
Arms are `S` (`BIN_S`) and `E` (`BIN_E`). Each round runs both once, in alternating order (S E, then E S, and so on).
`THREADS` is a list of tokens. `default` adds no flag. A number N adds `--max-concurrency N`. The default list is `default 16`.
Each thread setting runs both windows. Default `ROUNDS` is 3.

## How to run
```
BIN_S=/path/monerod-stock BIN_E=/path/monerod-fork \
SNAP_HEAVY=/path/snap_heavy SNAP_SMALL=/path/snap_small \
PEER=127.0.0.1:28080 PEER_RPC=127.0.0.1:28081 \
DD=/path/to/scratch/fastbox_dd OUT_BASE=/path/to/results \
./fb_stage.sh
```
- `PEER` is the exclusive P2P peer (`<peer-host>:28080` if remote). `PEER_RPC` is its RPC, used for the hash check.
- `DD` is a scratch data dir that the kit owns. `OUT_BASE` is the result dir.
- Optional: `THREADS`, `ROUNDS`, `P2P_PORT` (default 38080), `RPC_PORT` (default 38081).
- Test-only overrides: `END_HEAVY`, `END_SMALL`, `TIMEOUT_HEAVY`, `TIMEOUT_SMALL`, `IDLE_S`, `SETTLE_S`, `GOV_FILE`.

The driver first writes the path, sha256 (first 16) and `--version` line of each binary, `nproc`, the CPU model and free memory to `stage.log`.
It sets the CPU governor to `performance` with `sudo -n cpupower` if that works, and restores the old one at the end. If not, it logs that and goes on.
It aborts with `FASTBOX_DONE abort` on a missing binary or snapshot.

## Outputs
- `OUT_BASE/stage.log`: the last line is `FASTBOX_DONE <time>` (or `FASTBOX_DONE abort <time>`).
- `OUT_BASE/<heavy|small>_<threads>/results.csv`, `summary.txt` (last line `AB_COMPLETE`), and per-run `.log`, `.stdout`, `.mem.csv` (2 s sampler).
- results.csv columns: round, arm, start_h, end_h, blocks, wall_s, peak_anon_MB, peak_privdirty_MB, peak_rss_MB, read_MB, write_MB, tip_height, hash_match, post_idle_anon_MB, cpu_s, peer_cpu_s.
- `peer_cpu_s` is the peer node's utime+stime over the window, read from `/proc` for the PID that listens on the PEER port (found with `ss -ltnp`). It is `na` if that PID is not visible or not readable. The kit never signals it.
- Each run in `summary.txt` also gets the load average and a count of other monerod processes (information only).

## Scorer
```
python3 -I fb_table.py <OUT_BASE>
```
For each window and thread setting it prints, per arm, the median (min-max) of cpu_s, wall_s, peak_anon_MB, post_idle_anon_MB, blocks, CPU per block and peer_cpu_s.
It prints E against S as the percent change of the medians for cpu_s, wall_s, peak_anon_MB and CPU per block. Each is tagged `disjoint` if the two arms' ranges do not overlap, else `overlap`.
It prints the count of runs with hash_match yes, and it flags runs whose end_h is below END as `incomplete`. A final summary block lists all dirs and totals. Missing or partial dirs are reported, not fatal.

## Process safety
- The kit signals only PIDs it started itself. It never matches processes by name.
- It stops a node with RPC `stop_daemon`, then TERM, then KILL, on its own PID only.
- The peer (for example the box's own reference node) is only read from `/proc`. It is never signalled, and no kit port overlaps its ports.
- Before every run the kit refuses to go on if anything listens on `P2P_PORT` or `RPC_PORT`.
- It deletes `DD` only if `DD` holds the marker `.fastbox_scratch` that the kit created. It refuses a non-empty `DD` without the marker.
- Only `DD`, `OUT_BASE` and the kit's own ports are touched.
- The post-window idle sample bans the peer's host on our own node only (`set_bans`), then lifts the ban.

## Time
24 runs at the defaults (2 windows x 2 thread settings x 2 arms x 3 rounds). About 2 h on a 16-core box.
