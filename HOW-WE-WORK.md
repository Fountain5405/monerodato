# How the lab works

monerodato is built, tested and published by AI coding agents, with one human in charge. This page describes who does
what, how a change gets in, and how the numbers in this repository are produced. What was checked for each release is
in [VERIFICATION.md](VERIFICATION.md).

## Who does what

**The owner** is the one human. They choose what to work on, decide what ships, and give every public push and tag.
They do not review the code: **no human has verified that the optimisations are correct.**

**The agents.** Each agent runs in its own account, with its own files, and works on its own part:

| agent | role |
|---|---|
| optimizer | writes the changes, builds them, designs most measurements and scores them |
| adversary | tries to break each change: differential tests, fuzzing, mutant transactions, the release gate, and a review of every commit series |
| coordinator | runs the lab's machines and nodes, runs the measurement kits the other agents send, checks and places the evidence, and publishes |
| fee research | separate Monero research on fees; not part of monerodato's code |

**The models.** The optimizer, the coordinator and the fee agent are Claude Code agents running on Anthropic's Claude
models. The model (Opus or Fable) and the reasoning effort change from task to task and over time, so no single
model version produced the work. The adversary runs on a different backend, GLM 5.3.

Other agents in the lab work on other Monero research and do not touch monerodato.

**How they work together.** The agents do not share a session. They exchange messages and files through a shared
mailbox. A request to run something comes as a kit: scripts, inputs and a checksum list. The coordinator reads every
script before running it, treats agent files as untrusted, runs them under their own account, and sends the results
back as an archive with its checksum. The owner also directs each agent directly.

## How a change gets in

1. **The optimizer writes the change** on a lab branch, one idea per commit, so that each commit can be measured and
   ported on its own.
2. **Predictions come first.** Before any timed run, the optimizer writes down what it expects and what would count as
   a miss. The scored result is compared with that record, and misses are reported as misses.
3. **Runs alternate between the arms** (for example A B B A), with a fresh process and the same starting database
   for each run. A difference counts only when the two arms' ranges do not overlap; otherwise it is reported as no
   measurable change.
4. **Every figure is compared with the same thing measured the same way:** the same metric, block range and machine.
   Public figures are given as a percentage change in time, not as a speed ratio.
5. **The output must not change.** Replays check the chain's block hashes against an unmodified node. Prover changes
   must give byte-identical proofs. The adversary's corpus of real and mutated transactions must get the same verdicts
   from monerodato and from the unmodified build.
6. **The adversary reviews** the commit series and runs the gate. A release is tagged only after it approves and the
   owner says so.

## The machines

The measurements run on a range of hardware, described here by class only:

- low-end nodes: an Atom N450 netbook (1 core, 2 threads, under 1 GB of RAM, 5,400 rpm disk), a Pentium G6950 with a
  spinning disk, and a Core 2 Quad Q6600 with an SSD;
- a virtual machine on a 5,400 rpm disk, for the slow-disk tests;
- desktop machines: Ryzen 9 3900X, Ryzen 5 5600G and Ryzen 7 5900XT;
- an unmodified reference node, used as the source of truth for block hashes.

The lab's own nodes also run on the public FCMP++ stressnet, alongside volunteers' nodes. The lab watches all of them
with the [stressnet monitor](https://github.com/Fountain5405/stressnetmonitor); its public dashboard is
[stressnet.moneroworld.com](https://stressnet.moneroworld.com/).

## How results are published

- **Every number links to its data and the scripts that produced and scored it,** so that anyone can rerun the
  scoring and, with the same hardware class, the measurement. See [evidence/](evidence/).
- **Every text file says it was written by AI.**
- **Machine names, network addresses and local paths are replaced** before anything is published. The evidence is
  otherwise the agents' reports as written.
- **Nothing is pushed without the owner's direct go.**

## What is not public

The lab's internal records stay private: the working history before each release, the agents' mailbox, and the
adversary's review history (its reviews are cited here by hash).
